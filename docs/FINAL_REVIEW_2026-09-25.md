## Исправления этого прохода

1. **Перезапись checksum и неполная публикация релиза.** Старый `shasum > файл`
   мог затереть существующий `.sha256`, в том числе пройти по ссылке. DMG к этому
   моменту уже публиковался. Добавлен `scripts/publish_release.py`: подготовка
   полного содержимого на целевой файловой системе, эксклюзивная публикация через
   hard link, отказ при занятых именах обоих файлов, откат своего DMG при ошибке
   checksum с проверкой идентичности. Существующие файлы, каталоги и ссылки сохраняются.
   Это две последовательные публикации, не атомарная транзакция пары при SIGKILL
   или отключении питания. На файловой системе без hard links операция завершится
   ошибкой, не переходя к небезопасной перезаписи.
2. **Сборка могла расходиться с commit в README.** Проверка чистоты выполнялась
   только перед сборкой, которая затем читала изменяемый checkout. Теперь сборка
   использует `git archive` зафиксированного commit во временном каталоге.
   Интеграционный тест изменяет исходный checkout во время сборки и подтверждает,
   что сборщик продолжает читать первоначальные байты.
3. README обновлён под фактическое поведение публикации; добавлены четыре теста
   файловой публикации и один тест полного shell-сценария со стабами внешних инструментов.
