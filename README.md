# СберВакансии

Нативное macOS-приложение на SwiftUI для полной выгрузки вакансий работодателей группы и экосистемы Сбера через API hh.ru. Приложение не является официальным продуктом Сбера или HeadHunter.

## Возможности

- версионированный список работодателей в `employers.json`, копируемый в `Application Support/HHVacancySber` для последующего редактирования;
- typed-запросы к hh.ru и полная пагинация со сверкой количества записей: раздел, прочитанный не полностью, перечитывается один раз, а сохраняющиеся пропуски и ошибки показываются предупреждением по работодателям вместе с полученными вакансиями;
- два ограниченных повтора при ответах hh.ru 500/502/503/504 и кратковременных сбоях соединения;
- разбиение выдачи глубже ограничения API в 2000 результатов по регионам и датам;
- семидневный кэш дерева `/areas` с явно обозначенным использованием устаревших данных;
- строгая классификация региона: субъект/город, «Удалённо» или «Регион не определён»;
- фильтры работодателя и субъекта с AND-семантикой; фиксированный порядок вакансий — от новых к старым;
- избранное в формате v2 с автоматической миграцией v1, архивные статусы и PDF;
- кнопка «Статистика в PDF» справа в строке состояния: отчёт по текущему списку (вакансии или избранное) с учётом фильтров работодателя и региона, общей статистикой и названиями/датами вакансий от новых к старым. Фильтры входят в имя файла; используются только уже загруженные данные. Отсутствующие даты явно отмечаются в конце списка;
- текстовая подпись «IT · Данные · ИИ» без плашки и сине-зелёный текст всей карточки для технологических и аналитических вакансий; отдельная подпись «ИБ» и тёплая терракотово-персиковая гамма для информационной безопасности (с приоритетом над общим IT). Цвета адаптируются к светлой и тёмной теме и действуют также в полном описании и избранном; локальное распознавание по названию, профессиональным ролям и явным тематическим признакам в доступном тексте. Смежные общие навыки (например, резервное копирование и взаимодействие с регуляторами) считаются признаком ИБ в названии/профессиональной роли; стандартное требование соблюдать правила ИБ само по себе не выделяет вакансию. После загрузки описания направление может уточниться; автоматическое распознавание не гарантирует полноту;
- lazy-загрузка описания вакансии, в том числе для избранного вне текущей выдачи (описание сохраняется в избранном), и сохранение последней полной выдачи при ошибке обновления;
- отмена загрузки выборки и экспорта избранного в PDF той же кнопкой, которой они запущены; при отмене поиска сохраняется предыдущая полная выдача;
- вакансия избранного, которую hh.ru больше не отдаёт (HTTP 404), при проверке помечается как архивная.

Начальная конфигурация содержит 47 работодателей широкого поискового периметра Сбера: группу, экосистему и совместные предприятия. Основания, исторические раскрытия и ограничения проверки перечислены в [сверке от 05.09.2026](docs/SBER_EMPLOYER_PERIMETER_2026-09-05.md). BI.ZONE и Cloud.ru включены директивно по указанию пользователя; [идентификация на HH](docs/EMPLOYER_ADDITIONS_2026-09-06.md). Список не является перечнем юридически контролируемых дочерних обществ, не претендует на исчерпывающий охват и может редактироваться без пересборки.

## Требования и сборка

- Apple silicon, macOS 13.0 или новее;
- Xcode 15.2 или новее;
- встроенный application token hh.ru; правила безопасной проверки описаны в [чек-листе](HH_TOKEN_LOCAL_CHECKLIST.md).

```zsh
cd HHVacancySber
xcodebuild -project HHVacancySber.xcodeproj -scheme HHVacancySber \
  -configuration Debug -destination 'platform=macOS,arch=arm64' build
xcodebuild -project HHVacancySber.xcodeproj -scheme HHVacancySber \
  -configuration Debug -destination 'platform=macOS,arch=arm64' test
```

Два ограниченных live-теста реального API запускаются только явно и включаются раздельно: авторизация/описание (до двух запросов) и технологическая метка (один запрос, до 20 вакансий); команда и ограничения описаны в [документе о тестировании API](docs/HEADHUNTER_API_TESTING.md).

Тесты статистического PDF сохраняют и повторно открывают отчёты для 24 сочетаний работодателя/региона общего списка и 12 сочетаний избранного. Проверяются состав и порядок строк, счётчики, подписи фильтров, имена файлов, пустые выборки, офлайн-избранное, отмена, ошибки и повторная запись без дополнительных HH-запросов. UI-тесты проверяют общий безрамочный стиль PDF-команд, высоту 32 pt и выравнивание в статусной строке высотой 48 pt.

Локальные ресурсные сценарии без обращений к HH описаны в [benchmark-инструкции](scripts/benchmarks/README.md). Отмена удаляет ожидающий запрос из очереди; ограничения доступа HH останавливают PDF-enrichment, а повторный экспорт использует уже загруженные detail-данные текущей сессии.

Пользовательское имя приложения — `СберВакансии.app`, bundle ID — `local.sergey.HHVacancySber`. App Sandbox разрешает исходящие сетевые соединения и выбранные пользователем файлы.

## Конфигурация работодателей

Bundled-файл находится в `HHVacancySber/HHVacancySber/employers.json`. При первом запуске он атомарно копируется в контейнер App Sandbox: `~/Library/Containers/local.sergey.HHVacancySber/Data/Library/Application Support/HHVacancySber/employers.json`; далее runtime-файл является источником истины. Исключение — неизменённый прежний стандартный список из 11, 44 или 45 работодателей: при точном совпадении со одним из снимков `employers.legacy-v1.json` / `employers.legacy-44.json` / `employers.legacy-45.json` он атомарно обновляется до 47 записей. Любая пользовательская правка, включая порядок или комментарий, отключает эту миграцию. Пустой список, пустые или повторяющиеся ID и некорректная схема завершают поиск явной ошибкой — скрытого fallback нет. Там же лежат `favorites.json` и кэш регионов `areas.json`. Путь `~/Library/Application Support/HHVacancySber` приложение в песочнице не использует.

## Иконка и релиз

Канонический вектор новой зелёной пиктограммы — `HHVacancySber/Design/AppIcon.svg`. Скрипт `HHVacancySber/Scripts/render_icon.py` создаёт слоты 16–1024 через CairoSVG, `rsvg-convert`, macOS AppKit или Pillow и явно завершается ошибкой, если SVG-backend недоступен.

DMG собирается из чистого commit командой `scripts/release.sh --output-dir <directory>`. Скрипт проверяет Release-настройки, sandbox entitlements и итоговый образ.

При повторном экспорте избранного в тот же каталог занятые имена сохраняются: новый PDF получает суффикс `_2`, `_3` и далее. Каждый файл создаётся только под свободным именем (`O_CREAT | O_EXCL`), поэтому существующий файл не заменяется, даже если появился в последний момент. В каталоге остаются только PDF: при ошибке или отмене уже записанные в этом экспорте файлы удаляются, служебных каталогов нет. Явный выбор файла через системные панели личного и статистического PDF сохраняет прежний сценарий подтверждения замены.
